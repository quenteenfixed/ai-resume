核心项目深度分析

2.1 OpenClaw（373K★）— 心跳循环 + 文件式记忆

OpenClaw 是 2026 年 GitHub 增长最快的项目，其核心创新是将 Agent 从"请求-响应"模式转变为"持久循环"模式。 Agent 不是一个被动等待指令的聊天机器人，而是一个通过心跳定时唤醒、主动检查任务、自行决策的持久进程。

┌─ Gateway（网关进程）──────────────────────────────┐ │ WhatsApp · Telegram · Slack · Discord · iMessage │ │ ↓ 接收消息 → 标准化 → 路由到 Agent Loop │ │ ↑ 发送响应 → 过滤 HEARTBEAT_OK → 投递到平台 │ └──────────────────────────────────────────────────────┘ ↓ ┌─ Agentic Loop（代理循环）─────────────────────────┐ │ 1. 加载 SOUL.md（身份 + 价值观） │ │ 2. 加载 HEARTBEAT.md（定时任务清单） │ │ 3. 从 SQLite 检索相关记忆（语义搜索） │ │ 4. 调用 LLM（带完整上下文） │ │ 5. 执行工具/技能 │ │ 6. 结果写回 SQLite │ │ 7. 超出上下文窗口时自动压缩 │ └──────────────────────────────────────────────────────┘ ↓ ┌─ 存储 ────────────────────────────────────────────┐ │ SQLite（唯一数据库） │ │ ├── 对话历史（时间戳消息） │ │ ├── 语义嵌入（向量搜索 + sqlite-vec） │ │ ├── 压缩摘要（旧消息自动压缩） │ │ └── 配置文件（Markdown 格式） │ │ │ │ SOUL.md · HEARTBEAT.md · AGENTS.md · IDENTITY.md │ └──────────────────────────────────────────────────────┘

核心技术要点

  • Heartbeat 心跳调度：默认每 30 分钟唤醒一次，读取 HEARTBEAT.md 检查是否有事可做。无事可做时返回 HEARTBEAT_OK，Gateway 静默丢弃
  • SOUL.md 身份系统：定义 Agent 的人格、价值观、沟通风格、常驻指令——每次循环开始时加载到上下文顶部
  • 文件式记忆：所有配置和记忆都是人可读的 Markdown 文件，可 git 版本控制，可 grep 搜索
  • 上下文压缩：旧消息自动摘要压缩，最近 N 条保留原文。原始数据保留在独立表中供审计
  • 混合搜索：语义嵌入 + 关键词搜索，兼顾"意思相近"和"精确匹配"
  • HEARTBEAT_OK 过滤：心跳无事可做时不打扰用户，是优秀的 UX 设计
安全风险

OpenClaw 2026 年 3 月在 4 天内披露了 9 个 CVE（含 CVSS 9.9），源于 13K+ 社区技能缺乏审核。 这是"生态开放度"与"安全性"的典型矛盾——技能越多，攻击面越大。

2.2 Hermes Agent（95.6K★）— 自我改进 + 三层记忆

Hermes Agent 由 Nous Research 开发，核心创新是学习闭环： Agent 在完成任务后自动总结经验，生成可复用的"技能"文件，下次遇到类似任务直接加载使用。 这使得 Agent 的能力随使用时间指数增长。

Hermes 学习闭环（5 步） │ ├── 1. 接收任务 — 用户或定时触发 ├── 2. 检索上下文 — FTS5 全文搜索（~10ms / 10K+ 文档） │ 查找相关的过去技能和记忆 ├── 3. 推理并执行 — LLM 规划任务、调用工具、执行 ├── 4. 记录结果 — 如果任务涉及 5+ 工具调用 │ → 自动生成技能文件（agentskills.io 标准） └── 5. 持久化 — 技能索引到记忆，未来会话可用 # 三层记忆架构： Layer 1 — Session Memory 当前会话上下文（标准 LLM 管理） Layer 2 — Persistent Memory SQLite + FTS5（任务结果、技能文件、用户笔记） Layer 3 — User Model 自动构建用户偏好画像（编码风格、时区、协作者） # 性能数据： # 20+ 自创建技能后，同类任务完成速度提升 40% # 复杂任务平均成本 ~$0.30（预算模型）

核心技术要点

  • 技能自动生成：任务涉及 5+ 工具调用时自动创建技能文件，遵循 agentskills.io 开放标准
  • 技能自我改进：Agent 使用技能时评估效果，发现更优解自动更新技能文件——形成"创建→使用→评估→优化"闭环
  • FTS5 全文搜索：SQLite 原生 FTS5，10ms 延迟检索 10K+ 文档，无需额外向量数据库
  • 用户模型层：自动学习用户偏好（编码风格、时区、工具偏好），100+ 次交互后输出个性化
  • 118 个精选技能：安全审核的精选技能库，而非 13K+ 不审核的社区技能
  • 多模型路由：支持 OpenAI、Anthropic、Nous Portal、OpenRouter 等，可按任务复杂度路由到不同模型
核心启示

Hermes 的学习闭环解决了 Agent 领域最大的痛点：Agent 不在会话间学习。 传统 Agent 每次从零开始，Hermes 通过技能文件将经验沉淀为可复用资产。 20+ 技能后 40% 的速度提升是实打实的工程价值。

2.3 LangGraph（44K★）— 图状态机 + 检查点

LangGraph 是 LangChain 团队的图基 Agent 框架，核心是将 Agent 行为建模为状态机图， 每个节点是一个处理步骤，每条边是状态转换。其最大的工程价值是检查点系统： 每步自动保存完整状态快照，崩溃后可从任意节点恢复。

核心技术要点

  • 图状态机：Agent 行为建模为有向图，节点=处理步骤，边=条件转换。比纯 prompt 更可控、可调试
  • Checkpointer：每步自动保存状态快照。支持同步/异步两种模式，平衡性能和持久性
  • Delta Channels：新引入的增量存储——只存每步的 delta，定期全量快照。解决 O(N²) 存储增长问题
  • 短期+长期记忆：短期记忆 = Agent 状态的一部分（多轮对话）；长期记忆 = 跨会话的 Store（用户级/应用级）
  • PostgreSQL 后端：生产级存储后端，支持 PostgresSaver 和 PostgresStore
  • 人机协作：内置 interrupt 机制，可在任意节点暂停等待人类审批后继续

2.4 CrewAI（53K★）— 角色分工 + 认知记忆

CrewAI 将多 Agent 协作建模为企业团队：每个 Agent 有角色（role）、目标（goal）、背景（backstory）， 通过 Cognitive Memory 实现智能记忆管理。

核心技术要点

  • 角色化 Agent：每个 Agent 有明确的角色、目标、背景故事，通过 prompt 注入人格
  • Cognitive Memory：不是简单的向量存储，而是认知层——智能记忆、矛盾解决、主动遗忘、知道何时缺乏上下文
  • 层级化流程：支持层级式（hierarchical）流程，自动生成 Manager Agent 协调工作流、委派任务、验证结果
  • 私有 vs 共享记忆：Agent 可使用 Crew 共享记忆（默认），也可获得私有记忆范围
  • A2A 协议：支持 Agent-to-Agent 通信协议和 MCP 工具协议
  • Flows 状态管理：CrewAI Flows 提供事件驱动的状态管理，可构建复杂工作流

2.5 Letta / MemGPT（23K★）— 内存原生 + 梦想Agent

Letta（原 MemGPT）的核心思想是将 LLM 的上下文当作操作系统的内存来管理： 信息在"核心内存"和"归档内存"之间分页（page in/out），使 Agent 能持有远超上下文窗口的信息。

核心技术要点

  • 核心内存（Core Memory）：Agent 每轮都能看到的部分（人设块 + 角色块），修改即时持久化
  • 归档内存（Archival Memory）：外部向量存储（pgvector / SQLite / Pinecone），Agent 通过工具调用搜索
  • 梦想Agent（Dream Agents）：后台记忆Agent，在 Agent 空闲时变换 prompt、上下文和技能——"睡眠期计算"
  • 上下文仓库（Context Repositories）：Git 版本控制的 Agent 记忆，可编程管理上下文
  • 有状态服务：Agent 作为长生命周期服务运行，跨会话积累记忆，而非每次重新开始
与 Andon Labs 的呼应

Letta 的"核心内存"概念与 Andon Market 的"长期记忆注入上下文顶部"异曲同工。 Andon Labs 发现 Agent 经常忘记去检索记忆 → Letta 的方案是让关键信息始终在上下文中可见。 两者从不同路径得出了相同的结论：全量注入 > 主动检索。

2.6 Paperclip（37K★）— 治理层 + 审批 + 组织架构

Paperclip 是最接近 Andon Labs Pion 理念的开源项目。它不是 Agent 执行框架， 而是Agent 治理和管理层：将 AI Agent 组织成企业层级结构， 有汇报线、角色定义、预算管理、审批门和不可变审计。

核心技术要点

  • 组织架构：Agent 有 boss、title、job description，形成层级结构
  • 审批门（Approval Gates）：预算提升、高风险技能调用、招聘等操作排队等待人类审批
  • Token 预算：每个角色有月度 Token 预算，自动执行限制
  • 目标感知执行：任务携带完整的目标祖先链，让 Agent 始终看到"为什么"，而不只是"做什么"
  • 配置版本化：配置变更被版本化，坏变更可一键回滚
  • 不可变审计：每个对话、每个决策、每个工具调用全程追踪
  • Bring Your Own Agent：支持任何能接收心跳的 Agent（Claude、Cursor、Codex 等）
  • 自托管：完全自主部署，数据不离开你的基础设施

💓

高优先级
🧠

高优先级
📚

来源：Hermes Agent。完成复杂任务（5+工具调用）后自动生成技能文件。 下次类似任务直接加载，40%速度提升。技能可自我改进。
高优先级
🏛️
4. 治理与审批门
来源：Paperclip + Andon Andonos。组织架构 + 审批门 + Token预算 + 目标祖先链。 高风险操作排队等审批，配置可回滚。
中优先级
🔄
5. 检查点与增量存储
来源：LangGraph。每步自动保存状态快照，崩溃可从任意节点恢复。 Delta Channels 只存增量，解决 O(N²) 存储增长。
中优先级

来源：OpenClaw。SOUL.md 定义人格/价值观，HEARTBEAT.md 定义定时任务。 人可读、可 git 版本控制、可 grep 搜索。
中优先级

来源：CrewAI + Andon Market。每个 Agent 有角色/目标/背景。 层级化 Manager Agent 自动协调委派。私有 vs 共享记忆范围。
中优先级

8. 睡眠期计算

8.1 心跳调度系统（OpenClaw 式）

# core/scheduling/heartbeat.py — 借鉴 OpenClaw 心跳模式 import asyncio, yaml from pathlib import Path class HeartbeatScheduler: """心跳调度器：定时唤醒Agent，读取HEARTBEAT.md决定是否有事可做""" def __init__(self, agent, interval_minutes: int = 30): self.agent = agent self.interval = interval_minutes * 60 self.heartbeat_file = Path("HEARTBEAT.md") async def start(self): """启动心跳循环""" while True: await asyncio.sleep(self.interval) await self._tick() async def _tick(self): # 1. 读取 HEARTBEAT.md 任务清单 tasks = self._parse_heartbeat(self.heartbeat_file.read_text()) # 2. 对每项任务，让 Agent 判断是否需要行动 for task in tasks: result = await self.agent.evaluate(task) # 3. HEARTBEAT_OK = 无事可做，静默丢弃 if result == "HEARTBEAT_OK": continue # 4. 有事可做，执行并投递结果 await self.agent.execute_and_deliver(task, result) def _parse_heartbeat(self, content: str) -> list[str]: """解析 Markdown 清单为任务列表""" return [ line.lstrip("- ").strip() for line in content.splitlines() if line.strip().startswith("- ") ]

8.2 学习闭环（Hermes 式）

# core/learning/learning_loop.py — 借鉴 Hermes 学习闭环 class LearningLoop: """学习闭环：完成复杂任务后自动生成可复用技能 借鉴 Hermes Agent 的 5 步学习闭环 """ def __init__(self, llm, skill_store, fts5_index): self.llm = llm self.skills = skill_store self.fts5 = fts5_index # SQLite FTS5 全文搜索 async def retrieve_relevant_skills(self, task_desc: str) -> list: """检索相关技能：FTS5 全文搜索，~10ms""" results = await self.fts5.search(task_desc, limit=10) return [await self.skills.load(r["id"]) for r in results] async def maybe_create_skill(self, task, result): """如果任务涉及 5+ 工具调用，自动生成技能文件""" if len(result.tool_calls) < 5: return # 简单任务不生成技能 skill = await self.llm.generate( prompt=f"""基于以下任务和结果，创建一个可复用的技能文件。 任务：{task.description} 使用工具：{result.tool_calls} 结果：{result.summary} 成功：{result.success} 输出格式（agentskills.io 标准）： --- name: <技能名> description: <何时使用> steps: <执行步骤> tools: <需要的工具> --- """ ) skill_id = await self.skills.save(skill) await self.fts5.index(skill_id, skill) return skill_id async def improve_skill(self, skill_id: str, execution_feedback: dict): """使用技能时评估效果，发现更优解自动更新 形成"创建 → 使用 → 评估 → 优化"闭环 """ skill = await self.skills.load(skill_id) if execution_feedback["better_approach_found"]: updated = await self.llm.generate( prompt=f"更新技能 {skill_id}：{execution_feedback['improvement']}" ) await self.skills.update(skill_id, updated)

8.3 治理层（Paperclip + Andonos 式）

# governance/approval_gate.py — 借鉴 Paperclip 审批门 class ApprovalGate: """审批门：高风险操作排队等待人类审批 借鉴 Paperclip 的 approval gates + budget enforcement """ async def check_and_maybe_block(self, action: dict) -> bool: # 1. 检查是否需要审批 if not self._needs_approval(action): return True # 直接放行 # 2. 检查 Token 预算 role = action["agent_role"] if not self.budget.can_spend(role, action["estimated_tokens"]): await self._notify_budget_exceeded(role, action) return False # 3. 排入审批队列，推送通知 approval = await self._request_human_approval(action) return approval.approved def _needs_approval(self, action: dict) -> bool: # 付款、签合同、对外发送敏感信息 → 需审批 return action.get("requires_approval", False) or \ action.get("amount", 0) > self.approval_threshold # governance/config_versioning.py — 借鉴 Paperclip 配置版本化 class ConfigVersioning: """配置版本化：坏变更一键回滚 借鉴 Paperclip 的 revisioned config + one-click rollback """ async def save_version(self, config: dict): # 每次配置变更创建新版本 version_id = str(uuid.uuid4()) await self.db.save(version_id, config, timestamp=time.time()) return version_id async def rollback(self, target_version: str): # 一键回滚到指定版本 config = await self.db.load(target_version) await self._apply_config(config) await self.audit.record("config_rollback", target_version)

# infra/checkpoint.py — 借鉴 LangGraph 检查点 + Delta Channels from langgraph.checkpoint.postgres import PostgresSaver from langgraph.store.postgres import PostgresStore # 生产级配置：PostgreSQL 后端 DB_URI = "postgresql://user:pass@localhost:5432/agent_db" async def create_graph_with_checkpointing(): # Checkpointer：短期记忆，每步自动快照 checkpointer = PostgresSaver.from_conn_string(DB_URI) await checkpointer.setup() # Store：长期记忆，跨会话 store = PostgresStore.from_conn_string(DB_URI) await store.setup() # 构建图 builder = StateGraph(AgentState, context_schema=Context) builder.add_node("load_soul", load_soul_node) builder.add_node("retrieve_memory", retrieve_memory_node) builder.add_node("reason", reason_node) builder.add_node("execute_tools", execute_tools_node) builder.add_node("maybe_learn", maybe_learn_node) # Hermes 学习闭环 builder.add_node("persist", persist_node) # 条件边 builder.add_conditional_edges("reason", should_use_tools) builder.add_conditional_edges("execute_tools", should_continue_or_finish) # interrupt 节点：高风险操作暂停等审批（← LangGraph + Paperclip） builder.add_node("approval_check", approval_check_node) graph = builder.compile( checkpointer=checkpointer, store=store, interrupt_before=["approval_check"], # 审批前暂停 ) return graph
