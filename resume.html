AIBall Solo — 足球赛事数据分析与智能预测平台
全栈架构 | FastAPI + Vue 3 + PostgreSQL | 六路融合预测引擎
GitHub

项目概述

独立设计并实现的足球比赛数据分析与预测平台"足智AI"。系统以多路融合算法为核心，将赔率概率、历史交锋、进球期望、指数离散、欧亚一致性和凯利指数六大信号统一融合，生成胜平负概率、预期进球、Top-N 比分分布、风险等级和价值投注建议。支持 6 种预测模式（均衡/市场/数据/变化/保守/价值），并提供完整的用户权限体系、JWT 认证、可视化分析和 Agent 智能分析链路。

技术架构

  • FastAPI 后端构建 RESTful API，支持 GZip 压缩、CORS 中间件、MCP 端点挂载
  • Vue 3 + TypeScript + Vite 前端，Pinia 状态管理，ECharts 数据可视化
  • PostgreSQL 15 生产数据库 + SQLite 开发环境，支持幂等 upsert 写入
  • 六路融合预测算法：Shin 去 vig、ELO 评级、泊松分布、Dixon-Coles 比分矩阵校准、凯利准则、EV 价值评估
  • Agent 运行时可插拔架构：支持 Gemini / A2A / Ollama / Harness / Template 多运行时切换
  • 四层用户权限体系（游客/普通/体验/月付），动态控制数据可见范围
  • Docker Compose 一键部署 + Nginx 反向代理 + 健康检查 + 镜像自动回滚

核心技术亮点

  • 多路融合预测架构：六路信号加权融合，权重可按模式动态调整
  • Dixon-Coles 比分矩阵校准：修正低比分异常集中问题
  • 可解释概率输出：概率 + 置信度 + 风险评分 + 信号标记 + Top 比分
  • 风险控制系统：置信度校准、市场分歧检测、联赛准确率修正、伤停和赛程影响
  • Agent 评测系统：多运行时对比、工具调用检测、延迟统计、编造检测
  • 幂等数据处理管线：可重复运行，支持增量更新
  • 裸机部署脚本体系：install / deploy / release / backup / rollback 全套运维

02
AIBall Auto Collect — 多维赛事数据自动采集系统
数据工程 | Node.js + Puppeteer | 断点续采 + 增量落盘
GitHub

项目概述

面向竞彩足球数据的自动化采集系统，基于 Node.js + Puppeteer 构建。系统自动打开赛事页面，逐场采集历史交锋（JC）、胜平负赔率（SPF）、总进球大小球（ZJQ）三类维度数据。采用页面内 JavaScript 注入方案，通过 Puppeteer 调度页面、注入解析函数、调用 API 完成数据采集，支持断点续采、批量日期采集、增量落盘和失败重试。

技术架构

  • 纯 Puppeteer + 系统 Chrome，无需浏览器扩展依赖
  • 列表 API 直取模式：直接请求接口获取 matchId 列表
  • 页面内脚本注入：通过 page.addScriptTag 注入 parse-funcs.js，在页面上下文执行采集
  • 三页一站式采集：每场比赛自动遍历l
  • 增量合并存储：以 matchId 为唯一键，已存在则合并更新，不覆盖已有非空字段
  • 跨平台启动脚本：macOS/Linux shell + Windows PowerShell
  • 独立 Chrome 用户数据目录，避免污染日常浏览器

核心技术亮点

  • 页面内执行与页面外调度分离：collector / parse-funcs / storage 职责清晰
  • DOM 轮询等待机制：异步渲染表格就绪检测，避免数据未加载即采集
  • 断点续采：读取已有 matches.json 跳过已采集 matchId
  • 批量日期采集：batch_collect.sh 按日期区间逐日执行
  • 容错设计：单页失败不阻塞其他页，单场失败记录 error 继续
  • headful 模式保留浏览器 30 秒，便于人工处理验证码
  • 反检测：禁用 AutomationControlled 特征、独立 Chrome profile

03
AIBall XGBoost — 多维度赛事预测机器学习系统
机器学习 | Python + XGBoost + scikit-learn | 三模型融合 + Walk-Forward CV
GitHub

项目概述

基于 XGBoost 的足球比赛多维预测系统，使用 581 维赛前特征预测胜平负、进球数和比分分布。系统采用三层模型架构：XGBoost multi:softprob 分类模型预测胜平负概率，两个 XGBoost count:poisson 回归模型分别预测主客队进球期望，再通过 Poisson 外积 + Dixon-Coles 修正构建比分概率矩阵，最终将分类概率与比分矩阵概率加权融合生成最终共识概率。

技术架构

  • 三层模型架构：分类模型 + 双 Poisson 回归 + 比分矩阵融合
  • 特征工程管线：中位数填充 + ±5σ 异常值裁剪 + 训练/推理特征列严格对齐
  • 概率校准：Isotonic Regression 缓解 XGBoost 概率过度自信问题
  • Dixon-Coles 比分修正：低比分区域（0-0, 1-0, 0-1, 1-1）概率校正
  • 一致性融合：60% 分类概率 + 40% 比分矩阵概率 = 最终共识
  • Walk-Forward CV：防止未来数据泄漏的时间序列交叉验证
  • 截止日训练 + 增量训练模式：模拟真实生产环境滚动更新
  • 一键流水线：train → evaluate → predict 全自动执行

核心技术亮点

  • 多模型融合：分类 + 回归 + 矩阵三层架构，优于单一模型
  • 防时间泄漏设计：所有训练和评估严格按日期边界切分
  • 丰富的预测输出：原始/校准/矩阵/融合四套概率 + Top-N 比分 + 大小球
  • 完整评估体系：RPS、LogLoss、Brier Score、Accuracy、F1、校准曲线
  • 多基线对比：team_history_avg、global_naive、home_advantage、random_uniform
  • HTML + JSON 双格式评估报告，包含混淆矩阵和特征重要性
  • 配置驱动：training.yaml / predict.yaml / evaluate.yaml 全 YAML 管理

AIMap — 基于地图的客户数据智能采集系统
浏览器自动化 | Python + Playwright | 反检测 + 风控恢复
GitHub

项目概述

基于高德地图的 C 端商户线索智能采集系统。使用 Python + Playwright 启动真实 Chrome 浏览器，通过注入 MutationObserver 实时监听高德地图页面 DOM 变化，自动提取商户名称与联系电话。系统内置反检测指纹隐藏、风控弹窗识别、自动冷却恢复和人类行为模拟机制，采集结果去重后保存为 CSV / JSON，可直接用于线下门店客户挖掘与区域分群。

技术架构

  • Playwright 启动真实 Chrome（非 headless），使用持久化用户数据目录
  • MutationObserver 监听 DOM 变化，实时捕获商户详情卡片
  • 多选择器 + 全文本扫描 + 手机号/座机正则兜底的三层提取策略
  • 前端 JS 去重 + Python 后端去重双重保障
  • 反检测模块：隐藏 navigator.webdriver、伪造插件列表、修正权限 API
  • 风控检测：识别"操作过于频繁""安全验证"等关键词，自动冷却恢复
  • 人类行为模拟：随机鼠标移动、页面滚动、批次暂停

核心技术亮点

  • 抗页面改版：不依赖单一 DOM class，多选择器容错
  • 采集来源标记：panel / text-scan 区分，可用于准确率分析
  • 批次控制：每 15 条暂停 30 秒，模拟人工休息节奏
  • 代理配置支持：可用于 IP 风控规避场景
  • CDP 远程调试：用户和程序操作同一浏览器实例
  • 移除 Playwright 可疑启动参数，降低自动化特征暴露
  • 数据覆盖武汉、成都等城市，已采集 440+ 条商户记录

AI 开发理念与实践

需求驱动、文档先行、AI 派发 — AI 时代的工程方法论

"AI 时代的开发，优先定好和想清楚需求、文档，再派发任务给 AI。"

在 AI 辅助开发成为主流的当下，核心能力已从"亲自编写每一行代码"转变为"精准定义需求、设计系统架构、编排 AI 工作流"。我始终遵循需求先行 → 文档驱动 → AI 派发 → 验证闭环的开发方法论：首先深入分析业务场景，明确系统边界与核心算法逻辑；其次以结构化文档（需求规格 / 算法设计 / 技术方案）固化思考成果；然后将具体实现任务派发给 AI 工具执行；最后通过自测、指标评估和基线对比完成验证。

这一方法论贯穿全部 6 个项目的开发过程。以足球预测系统为例：从需求定义（六路融合预测架构设计）、到 ML 管线设计（XGBoost + Poisson + Dixon-Coles 三模型融合方案）、到置信度与风险因子逻辑分析、再到开发与测试验证，每一步均以对话文档形式沉淀，形成可追溯的开发链路。以下是部分 AI 开发过程对话记录，完整展示了从需求到落地的思考路径。
